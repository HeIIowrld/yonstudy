## 4. 오디오 형식별 저장 용량

같은 6분 37초(396초) 강의를 형식별로 뽑아 측정했다.

| 형식 | 분당 | 697편(≈520시간) 환산 | 추출 시간 |
|---|---:|---:|---:|
| `wav` 16 kHz mono s16le | 1.83 MB | **55.8 GB** | 1.5초 |
| `flac` 16 kHz mono | 1.78 MB | 54.3 GB | 1.8초 |
| **`opus` 16 kHz mono 24 kbps** | **0.17 MB** | **5.2 GB** | 4.9초 |

디스크 여유가 54 GB라 **`wav`/`flac`는 애초에 불가능**했다.
16 kHz 음성은 이미 정보량이 줄어 있어 `flac` 무손실 압축이 거의 효과가 없다.

4편(126분)을 추출한 결과는 0.169 MB/분으로 추정치 0.17과 일치했고, 전체 용량은 20 MB였다.

```
ffmpeg -i <m3u8> -vn -ac 1 -ar 16000 -c:a libopus -b:a 24k -f opus out.opus
```

- HLS m3u8은 **쿠키 없이 열린다** (인증이 URL 경로 서명에 있음)
- 오디오만 가져오므로 영상 스트림은 내려받지 않으며, 6분 강의도 1.5초면 추출한다.
- 임시 파일명이 `.opus.part`면 ffmpeg가 컨테이너를 추론하지 못한다. 따라서 `-f opus`를 명시한다.

## 5. ASR 벤치마크(CPU 전용, Ryzen 7 8745HS 14스레드)

한국어 강의 13.4분(경영정보시스템 "Gen AI 기반 VBA 코드 작성 및 응용"),
faster-whisper int8, `vad_filter=True`, `beam_size=1`.

| 설정 | 소요 | RTF | 실시간 대비 |
|---|---:|---:|---:|
| `base` | 0.5분 | 0.040 | 25배 |
| `small` | 1.1분 | 0.081 | 12배 |
| `small` + 수동 핫워드 | 1.1분 | 0.083 | 12배 |
| `small` + **강의안 자동 핫워드** | 0.8분 | 0.057 | 17배 |

520시간 전량으로 환산하면 `base`는 약 21시간, `small`은 약 42시간이 걸린다.

### 품질: 같은 문장의 단계별 교정 결과

```
base                       …VBA 코드 작성과 그 음영에…      그릇에 크기도 다르고   생상도
                           위치나 크기식상 폰트도 다릅니다
small                      …그 음용에…                    글자 크기도 ✓         색상도 ✓
small + 수동 hotword        …VBA ✓ … 그 음용에…            위치나 크기, 색상, 폰트가 모두 ✓
small + 강의안 자동 hotword   …VBA ✓ 코드, 작성과 그 응용에 ✓…  위치나 크기, 색상, 폰트가 모두 ✓
```

핫워드 비용은 사실상 0인데 고유명사 표기와 조사 경계가 눈에 띄게 교정된다.
단, **목록에 있는 단어만** 고쳐진다. 수동 목록에 `응용`을 빠뜨렸더니 `음용`이 그대로 남았다.
강의안 PDF에서 자동 추출(13쪽 → 43개)하니 `응용`이 들어가 교정됐다.

"강의안을 같이 넣으면 전사가 좋아진다"는 설계 가설은 실측으로 확인됐다.

### VibeVoice-ASR-BitNet 검토 결과

| | ASR 7B | **ASR-BitNet** |
|---|---|---|
| 크기 | 7B(VRAM 16 GB+) | 1.58 GB, ~0.3B, CPU |
| 한국어 | 고품질 | **WER 11.15%** |
| 타임스탬프/화자 분리/핫워드 | 모두 ○ | **문서화 없음** |

BitNet은 7B의 양자화판이 아니라 **별개의 소형 모델**이다.
타임스탬프, 화자 분리, 핫워드가 없으면 슬라이드 정렬과 자막 생성이 성립하지 않는다.
속도를 높이는 대신 품질을 포기하는 선택지이므로, 자막 정본은 Whisper 계열로 만든다.

### 한국어 음성과 영어 슬라이드

생산시스템분석 강의는 한국어 음성과 영어 슬라이드로 구성되어 있다.

전사와 슬라이드가 공유하는 토큰이 **3개**(`eoq`, `mrp`, `ww`)뿐이다.
그런데 DTW는 항상 경로를 하나 만들어내므로 **그럴듯한 가짜 타임라인**이 나왔다
(p.13이 13:07~38:52을 통째로 먹는 식).

문자 체계를 감지해 언어가 다르면 **타임라인을 만들지 않고** 구간별 핵심어만 낸다.
언어에 영향을 받지 않는 대안은 영상 프레임에서 슬라이드 전환을 감지하는 것이다.
