## 4. 오디오 추출 — 형식 선택이 가능/불가능을 갈랐다

같은 6분37초(396초) 강의를 형식별로 뽑아 측정:

| 형식 | 분당 | 697편(≈520시간) 환산 | 추출 시간 |
|---|---:|---:|---:|
| wav 16k mono s16le | 1.83 MB | **55.8 GB** | 1.5초 |
| flac 16k mono | 1.78 MB | 54.3 GB | 1.8초 |
| **opus 16k mono 24kbps** | **0.17 MB** | **5.2 GB** | 4.9초 |

디스크 여유가 54GB라 **wav/flac는 애초에 불가능**했다.
16kHz 음성은 이미 정보량이 줄어 있어 flac 무손실 압축이 거의 먹히지 않는다.

**실제 4편(126분) 추출 결과**: 0.169 MB/분 — 추정치 0.17과 일치. 20MB.

```
ffmpeg -i <m3u8> -vn -ac 1 -ar 16000 -c:a libopus -b:a 24k -f opus out.opus
```

- HLS m3u8은 **쿠키 없이 열린다** (인증이 URL 경로 서명에 있음)
- 오디오만 가져오므로 영상 스트림은 내려받지도 않는다 — 6분 강의가 1.5초
- 함정: 임시 파일명이 `.opus.part`면 ffmpeg가 컨테이너를 추론 못 해 죽는다 → `-f opus` 명시

## 5. ASR 벤치마크 (CPU 전용, Ryzen 7 8745HS 14스레드)

한국어 강의 13.4분(경영정보시스템 "Gen AI 기반 VBA 코드 작성 및 응용"),
faster-whisper int8, `vad_filter=True`, `beam_size=1`.

| 설정 | 소요 | RTF | 실시간 대비 |
|---|---:|---:|---:|
| `base` | 0.5분 | 0.040 | 25배 |
| `small` | 1.1분 | 0.081 | 12배 |
| `small` + 수동 hotword | 1.1분 | 0.083 | 12배 |
| `small` + **강의안 자동 hotword** | 0.8분 | 0.057 | 17배 |

**520시간 전량 환산**: `base` 약 21시간, `small` 약 42시간 연산.

### 품질 — 같은 문장이 단계별로 어떻게 고쳐지는가

```
base                       …VBA 코드 작성과 그 음영에…      그릇에 크기도 다르고   생상도
                           위치나 크기식상 폰트도 다릅니다
small                      …그 음용에…                    글자 크기도 ✓         색상도 ✓
small + 수동 hotword        …VBA ✓ … 그 음용에…            위치나 크기, 색상, 폰트가 모두 ✓
small + 강의안 자동 hotword   …VBA ✓ 코드, 작성과 그 응용에 ✓…  위치나 크기, 색상, 폰트가 모두 ✓
```

**핵심**: hotword 비용은 사실상 0인데 고유명사 표기와 조사 경계가 눈에 띄게 교정된다.
단 **목록에 있는 단어만** 고쳐진다 — 수동 목록에 `응용`을 빠뜨렸더니 `음용`이 그대로 남았다.
강의안 PDF에서 자동 추출(13쪽 → 43개)하니 `응용`이 들어가 교정됐다.

**설계의 핵심 주장("강의안을 같이 넣으면 전사가 좋아진다")이 추측이 아니라 측정된 사실이 됐다.**

### VibeVoice-ASR-BitNet 검토 결과 — 자막 정본으로는 부적합

| | ASR 7B | **ASR-BitNet** |
|---|---|---|
| 크기 | 7B (VRAM 16GB+) | 1.58GB, ~0.3B, CPU |
| 한국어 | 고품질 | **WER 11.15%** |
| 타임스탬프 / 화자분리 / hotword | 모두 ○ | **문서화 없음** |

BitNet은 7B의 양자화판이 아니라 **별개의 소형 모델**이다.
타임스탬프·화자분리·hotword가 없으면 슬라이드 정렬과 자막 생성이 성립하지 않는다.
속도를 사는 물건이지 품질을 사는 물건이 아니다 → 자막 정본은 whisper 계열로 간다.

## 6. 슬라이드 ↔ 전사 정렬

**되는 경우** (영어 슬라이드 + 영어 자막, 딥러닝개론 45분 / 20쪽)

```

```

DTW 단조 정렬이 45분 전체를 슬라이드에 배분하고, 설명 분량 차이까지 반영한다.

**안 되는 경우** (한국어 음성 + 영어 슬라이드, 생산시스템분석)

전사와 슬라이드가 공유하는 토큰이 **3개**(`eoq`, `mrp`, `ww`)뿐이다.
그런데 DTW는 항상 경로를 하나 만들어내므로 **그럴듯한 가짜 타임라인**이 나왔다
(p.13이 13:07~38:52을 통째로 먹는 식).

→ 문자 체계를 감지해 언어가 다르면 **타임라인을 만들지 않고** 구간별 핵심어만 낸다.
근본 해결책은 영상 프레임의 슬라이드 전환 감지 — 언어와 무관하게 동작한다.

**강의안 페어링도 위치로 하면 틀린다.** 처음엔 "같은 제목 → 같은 주차" 순으로 골랐는데,
생산시스템분석 2주차(EOQ/QR 재고모델) 강의에 `Lecture 3-MRP.pdf`(다른 주제)를 붙였다.
→ 후보를 넓게 모아 전사 내용과 대조해 고르도록 바꿨고, 이제 올바른
`Lecture 2-Inventory Management.pdf`(0.51)를 선택한다. 최고 점수가 임계 미만이면 진행하지 않는다.
