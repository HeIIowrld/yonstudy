# 학습 도우미: 전사, 정렬, 노트

## 파이프라인

```
동영상 ──ffmpeg──▶ 오디오(opus) ──ASR──▶ 전사 ──┐
 (HLS)                                        ├─▶ 정렬 ─▶ 슬라이드별 타임라인 ─▶ 노트
강의안 PDF ──텍스트 추출──▶ 슬라이드 ──hotword──┘
```

## 1. 오디오 추출(`vod.py`)

```
ffmpeg -i <m3u8> -vn -ac 1 -ar 16000 -c:a libopus -b:a 24k -f opus out.opus
```

이 파이프라인에서는 영상을 저장하지 않는다. 형식 선택 근거는
[FINDINGS §4](FINDINGS.md#4-오디오-형식별-저장-용량)에 정리했다.
`opus` 24 kbps로 추출하면 697편 전량이 5.2 GB지만, `wav`는 55.8 GB로 디스크 여유를 넘긴다.

HLS m3u8은 쿠키 없이 열린다(URL 경로 서명 인증). 서명이 만료되면
`refresh_hls_url()`이 뷰어를 다시 열어 갱신한다.

## 2. 하드웨어별 ASR 구성

상위 코드는 OpenAI 호환 엔드포인트 하나만 보게 하고, 백엔드는 설정으로 흡수한다.

| 티어 | 조건 | 엔진 | 핫워드 | 화자 분리 |
|---|---|---|---|---|
| **A** | VRAM ≥ 16 GB | VibeVoice-ASR 7B | ○ | ○ |
| **B** | VRAM 6~12 GB | faster-whisper large-v3 + PyAnnote | ○ | ○ |
| **C** | CPU only | faster-whisper small/base (int8) | ○ | △ |

현재 측정 환경은 GPU가 없어 Tier C다. 실측 성능은 [FINDINGS §5](FINDINGS.md#5-asr-벤치마크cpu-전용-ryzen-7-8745hs-14스레드)에 정리했다.
CPU에서도 실시간의 12~25배로 돌아 520시간 전량이 21~42시간 연산이면 끝난다.

A와 B를 동시에 사용할 수 있으면 VibeVoice의 문장·화자 정보와 WhisperX의 단어 타임스탬프를 병합한다.

### VibeVoice-ASR-BitNet은 자막 정본으로 쓰지 않는다

7B의 양자화판이 아니라 별개의 소형 모델(~0.3B, 1.58 GB)이다.
한국어 WER은 11.15%이며 타임스탬프, 화자 분리, 핫워드는 문서화돼 있지 않다.
이 기능들이 없으면 아래 §3과 §4가 성립하지 않는다. RAG 인덱싱용 초벌 전사에는 쓸 수 있다.

## 3. 강의안 기반 핫워드 자동 추출

강의안에서 용어를 뽑아 ASR에 넘긴다. faster-whisper의 `hotwords=`와
VibeVoice-ASR의 사용자 지정 핫워드가 이를 지원한다.

`studykit.align.extract_hotwords()`는 다음 용어를 추출한다.

- 라틴 약어와 전문어(강의안의 표기를 그대로 유지: `vba`가 아니라 `VBA`)
- 강의안에 2회 이상 나오는 한글 2~6자 용어
- 제목에 든 말(1회만 나와도 그 강의의 핵심어)

### 측정 결과

```
base                       …VBA 코드 작성과 그 음영에…      그릇에 크기도 다르고   생상도
small                      …그 음용에…                    글자 크기도 ✓         색상도 ✓
small + 수동 hotword        …VBA ✓ … 그 음용에…            위치나 크기, 색상, 폰트가 모두 ✓
small + 강의안 자동 hotword   …VBA ✓ 코드, 작성과 그 응용에 ✓…  위치나 크기, 색상, 폰트가 모두 ✓
```

비용은 RTF +2% 수준으로 사실상 0이다. 다만 **목록에 있는 단어만** 고쳐진다.
수동 목록에 `응용`을 빠뜨렸더니 `음용`이 그대로 남았고, 강의안에서 자동 추출하니 교정됐다.
따라서 목록을 손으로 작성하지 않고 강의안에서 자동으로 추출한다.

현재는 한국어 조사가 붙은 형태(`디자인을`, `파일로`, `매출액이`)도 목록에 들어간다.
핫워드 매칭이 느슨해 큰 문제는 없지만, 조사를 제거하면 목록 품질을 높일 수 있다.

## 4. 슬라이드 ↔ 전사 정렬(`align.py`)

강의는 슬라이드를 **순서대로** 넘어간다. 이 단조성을 제약으로 걸면 임베딩 모델 없이도
정렬이 상당히 맞는다.

```
1. 슬라이드 텍스트와 전사 청크(45초)를 TF-IDF 벡터화   (순수 파이썬, 의존성 없음)
2. 코사인 유사도 행렬
3. DTW로 단조 경로 탐색 → "슬라이드 k는 t1~t2 구간"
4. 슬라이드 간 텍스트 증분(added/removed)을 그 구간 전사와 대조
   → 슬라이드에 없는데 말로만 한 설명 = 필기해야 할 내용
```

### 확인된 제한

#### 강의안 위치 기반 페어링

"같은 제목, 같은 주차" 순으로 고르면 강좌마다 제목 규칙이 달라 엉뚱한 장을 집는다.
VOD `2주차 1차시 온라인 강의: Inventory management(2)`와 PDF `Lecture 2-…`,
`Lecture 3-MRP.pdf`를 비교했을 때 주차 폴백이 다른 주제인 MRP를 골랐다.
후보를 넓게 모아 전사 내용과 대조해 고른다. 최고 점수가 임곗값(0.08) 미만이면
"강의안이 아카이브에 없을 수 있다"고 알리고 진행하지 않는다.

#### 서로 다른 언어의 음성과 슬라이드

공유 토큰이 **3개**(`eoq`, `mrp`, `ww`)뿐이었는데 DTW는 항상 경로를 만들어내므로
**그럴듯한 가짜 타임라인**이 나왔다(p.13이 25분을 통째로 먹는 식).
문자 체계를 감지해 언어가 다르면 타임라인을 만들지 않고 구간별 핵심어만 낸다.
영상 프레임의 슬라이드 전환 감지는 언어와 무관하게 동작하므로
한국어 강의가 다수인 이 아카이브의 우선 구현 대상이다.

## 5. 산출물(`report.py`)

`python3 cli.py analyze --cmid N`이 만드는 파일은 다음 형식이다.

```markdown
### p.5 · 03:29 ~ 13:23
- 일치도 `0.37`
- 슬라이드가 새로 꺼낸 것: algorithm, based, data, between
- 💬 말로만 나온 것: (전사에는 있는데 슬라이드에 없는 용어)
> (이 구간의 전사)
```

`store/courses/<학기>/<과목>/notes/<제목>.md`에 저장된다.

## 6. 아직 안 만든 것

다음 기능은 설계만 있고 아직 구현하지 않았다. 자세한 내용은 [ROADMAP](ROADMAP.md)에 있다.

- 주석 달린 강의안 PDF (여백에 "말로만 한 설명" 삽입)
- 용어집, 1분·5분·15분 요약, 예상 문제, Anki 덱
- 아카이브 전체 RAG: sqlite-vec와 학기, 과목, 주차, 출처 유형 메타데이터 필터
- 복습용 오디오(VibeVoice-TTS로 요약을 두 화자의 문답 형식으로 변환)
- 재녹음 시 노트 diff 병합("이번 보강에서 추가된 내용")
