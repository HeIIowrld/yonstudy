# 학습 도우미 — 전사·정렬·노트

## 파이프라인

```
동영상 ──ffmpeg──▶ 오디오(opus) ──ASR──▶ 전사 ──┐
 (HLS)                                        ├─▶ 정렬 ─▶ 슬라이드별 타임라인 ─▶ 노트
강의안 PDF ──텍스트 추출──▶ 슬라이드 ──hotword──┘
```

## 1. 오디오 추출 (`vod.py`)

```
ffmpeg -i <m3u8> -vn -ac 1 -ar 16000 -c:a libopus -b:a 24k -f opus out.opus
```

**영상은 저장하지 않는다.** 형식 선택 근거는 [FINDINGS §4](FINDINGS.md#4-오디오-추출--형식-선택이-가능불가능을-갈랐다):
opus 24kbps로 697편 전량이 5.2GB, wav였으면 55.8GB로 디스크를 넘긴다.

HLS m3u8은 쿠키 없이 열린다(URL 경로 서명 인증). 서명이 만료되면
`refresh_hls_url()`이 뷰어를 다시 열어 갱신한다.

## 2. ASR 3티어 — 하드웨어에 맞춰 고른다

상위 코드는 OpenAI 호환 엔드포인트 하나만 보게 하고, 백엔드는 설정으로 흡수한다.

| 티어 | 조건 | 엔진 | hotword | 화자분리 |
|---|---|---|---|---|
| **A** | VRAM ≥ 16GB | VibeVoice-ASR 7B | ○ | ○ |
| **B** | VRAM 6~12GB | faster-whisper large-v3 + PyAnnote | ○ | ○ |
| **C** | CPU only | faster-whisper small/base (int8) | ○ | △ |

현재 측정 환경은 GPU가 없어 Tier C. 실측 성능은 [FINDINGS §5](FINDINGS.md#5-asr-벤치마크-cpu-전용-ryzen-7-8745hs-14스레드).
CPU에서도 실시간의 12~25배로 돌아 520시간 전량이 21~42시간 연산이면 끝난다.

A·B가 동시에 가능하면 **VibeVoice의 문장·화자 + WhisperX의 단어 타임스탬프를 병합**하는 게 최상.

### VibeVoice-ASR-BitNet은 자막 정본으로 쓰지 않는다

7B의 양자화판이 아니라 별개의 소형 모델(~0.3B, 1.58GB)이다.
한국어 WER 11.15%에 타임스탬프·화자분리·hotword가 문서화돼 있지 않다.
그게 없으면 아래 §3·§4가 성립하지 않는다. RAG 인덱싱용 초벌 전사에는 쓸 수 있다.

## 3. ★ 강의안 hotword 자동 추출 — 이 시스템의 승부처

강의안에서 용어를 뽑아 ASR에 넘긴다. faster-whisper의 `hotwords=`와
VibeVoice-ASR의 커스텀 hotword가 모두 지원한다.

**`studykit.align.extract_hotwords()`가 뽑는 것**

- 라틴 약어·전문어 — **강의안의 표기를 그대로 유지**한다 (`vba`가 아니라 `VBA`)
- 강의안에 2회 이상 나오는 한글 2~6자 용어
- 제목에 든 말 (1회만 나와도 그 강의의 핵심어)

**효과 (실측)**

```
base                       …VBA 코드 작성과 그 음영에…      그릇에 크기도 다르고   생상도
small                      …그 음용에…                    글자 크기도 ✓         색상도 ✓
small + 수동 hotword        …VBA ✓ … 그 음용에…            위치나 크기, 색상, 폰트가 모두 ✓
small + 강의안 자동 hotword   …VBA ✓ 코드, 작성과 그 응용에 ✓…  위치나 크기, 색상, 폰트가 모두 ✓
```

비용은 RTF +2% 수준으로 사실상 0. 다만 **목록에 있는 단어만** 고쳐진다 —
수동 목록에 `응용`을 빠뜨렸더니 `음용`이 그대로 남았고, 강의안에서 자동 추출하니 교정됐다.
**목록을 손으로 쓰지 않고 강의안에서 뽑는 것이 요점이다.**

> 개선 여지: 한국어 조사가 붙은 형태(`디자인을`, `파일로`, `매출액이`)가 섞여 들어간다.
> hotword 매칭이 느슨해 큰 해는 없지만 조사 제거를 넣으면 목록 품질이 올라간다.

## 4. 슬라이드 ↔ 전사 정렬 (`align.py`)

강의는 슬라이드를 **순서대로** 넘어간다. 이 단조성을 제약으로 걸면 임베딩 모델 없이도
정렬이 상당히 맞는다.

```
1. 슬라이드 텍스트와 전사 청크(45초)를 TF-IDF 벡터화   (순수 파이썬, 의존성 없음)
2. 코사인 유사도 행렬
3. DTW로 단조 경로 탐색 → "슬라이드 k는 t1~t2 구간"
4. 슬라이드 간 텍스트 증분(added/removed)을 그 구간 전사와 대조
   → 슬라이드에 없는데 말로만 한 설명 = 필기해야 할 내용
```

### 실측으로 드러난 함정 두 가지

**① 강의안 페어링을 위치로 하면 틀린다.**
"같은 제목 → 같은 주차" 순으로 고르면 강좌마다 제목 규칙이 달라 엉뚱한 장을 집는다.
실측: VOD `2주차 1차시 온라인 강의: Inventory management(2)` ↔ PDF `Lecture 2-…` / `Lecture 3-MRP.pdf`
— 주차 폴백이 **MRP(다른 주제)**를 골랐다.
→ 후보를 넓게 모아 **전사 내용과 대조해** 고른다. 최고 점수가 임계(0.08) 미만이면
"강의안이 아카이브에 없을 수 있다"고 알리고 진행하지 않는다.

**② 한국어 음성 + 영어 슬라이드는 텍스트 정렬이 원리적으로 불가능하다.**
공유 토큰이 **3개**(`eoq`, `mrp`, `ww`)뿐이었는데 DTW는 항상 경로를 만들어내므로
**그럴듯한 가짜 타임라인**이 나왔다(p.13이 25분을 통째로 먹는 식).
→ 문자 체계를 감지해 언어가 다르면 타임라인을 만들지 않고 구간별 핵심어만 낸다.
근본 해결책은 **영상 프레임의 슬라이드 전환 감지** — 언어와 무관하게 동작하므로
한국어 강의가 다수인 이 아카이브에서는 이쪽이 본선이다.

## 5. 산출물 (`report.py`)

`python3 cli.py analyze --cmid N` 이 만드는 것:

```markdown
### p.5 · 03:29 ~ 13:23
- 일치도 `0.37`
- 슬라이드가 새로 꺼낸 것: algorithm, based, data, between
- 💬 말로만 나온 것: (전사에는 있는데 슬라이드에 없는 용어)
> (해당 구간 전사)
```

`store/courses/<학기>/<과목>/notes/<제목>.md` 에 저장된다.
